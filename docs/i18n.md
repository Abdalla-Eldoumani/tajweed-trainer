# Bilingual UI (English / Arabic)

The app translates between English and Arabic across UI chrome, lesson content, common-mistake lists, surah names, weekday letters, and the 404 page; toggle via the language pill in the sidebar.

## Anatomy

### `src/lib/i18n.ts`

A flat dictionary keyed by string ID, valued by `{ en, ar }`; keys use dot-notation for grouping:

```ts
"home.startLearning": { en: "Start Learning", ar: "ابدأ التعلّم" },
"weekday.short.0":    { en: "S", ar: "ح" },
```

Current top-level namespaces:

| Namespace | Purpose |
|---|---|
| `home.*`, `nav.*`, `learn.*`, `mushaf.*`, `practice.*`, `progress.*`, `settings.*` | Page chrome and navigation. |
| `module.*`, `ghunnah.*` | Per-module lesson labels. |
| `weekday.short.*` | Streak-counter weekday letters. |
| `review.*` | Spaced-repetition page and stats card. |
| `memorize.*`, `mushaf.memorize*` | Memorization tracker, recall mode, and Mushaf toolbar labels. |
| `search.*` | Global search page. |
| `speech.*` | TTS button labels (UI prompts only). |
| `insights.*` | Anonymous analytics card on `/progress`. |
| `learn.sectionsRead`, `learn.nextUnread` | Lesson section progress chip. |
| `settings.backup.*` | Backup and restore UI. |

`useTranslation()` is the hook every component uses:

```tsx
const { t, lang, isAr, dir } = useTranslation();
// t("home.startLearning") -> "Start Learning" | "ابدأ التعلّم"
```

### `src/components/layout/AppProvider.tsx`

Wraps every route with `SettingsProvider` (state) plus `SettingsSync`, a child effect that mirrors `settings.language` to `<html lang>` and `<html dir>`, which makes `dir="rtl"` flip globally when the user selects Arabic.

## Two layers of bilingual content

### 1. Chrome (i18n.ts)

UI strings (button labels, navigation, error messages, settings labels, weekday letters, mushaf labels): anything that isn't tajweed content. Add a key to `i18n.ts` and reference it via `t(key)`; never inline an Arabic string in JSX, which bypasses the i18n layer.

### 2. Tajweed content (JSON files)

Lesson content lives in `src/data/content/*.json`; every visible English field has an optional `_ar` counterpart:

| English field | Arabic counterpart |
|---------------|--------------------|
| `title_en` | `title_ar` (always present) |
| `description` | `description_ar` |
| `common_mistakes[]` | `common_mistakes_ar[]` |
| `rule_applied` | `rule_applied_ar` |
| `surah_name_en` | `surah_name_ar` (auto-filled by the script) |
| `translation` | `translation_ar` (optional; many examples skip it) |
| `condition` | `condition_ar` |
| `note` | `note_ar` |
| `introduction` | `introduction_ar` |
| `definition` | `definition_ar` |

Components read the `_ar` field or fall back to English via the `useTranslation().isAr` flag.

## How surah names get their Arabic

`scripts/fetch-surah-names.mjs` is a one-shot dev script that pulls `https://api.quran.com/api/v4/chapters` (114 surahs with `name_arabic`), writes `src/data/content/surah-index.json` (committed, the offline fallback), and patches `surah_name_ar` from `name_arabic` into every rule example that has `surah_name_en` but no `surah_name_ar`. Run it whenever you add an example referencing a new surah or the `/chapters` API gets new data:

```bash
node scripts/fetch-surah-names.mjs
```

Commit the resulting JSON changes.

## Hydration-safe localStorage

`useSettings()` reads from localStorage after mount: server HTML uses default settings (English, no bookmarks), then the client hydrates and re-renders with the actual settings. To avoid React hydration warnings on localStorage-driven UI (like the bookmark icon's `fill`), use the `mounted` pattern:

```tsx
const [mounted, setMounted] = useState(false);
useEffect(() => setMounted(true), []);
const isBookmarked = mounted && bookmarks.includes(page);
```

## RTL handling

- `dir="rtl"` and `lang="ar"` are set on `<html>` by `SettingsSync`.
- All Arabic text is wrapped in `<ArabicText>` or `<TajweedText>`, which set `dir="rtl"` and `lang="ar"` themselves regardless of surrounding direction.
- Tailwind logical properties (`ms-*`, `me-*`, `ps-*`, `pe-*`, `border-s`, `border-e`) so margins and borders flip correctly under RTL.
- For arrows, prefer SVGs that carry the geometry (`<polyline points="15 18 9 12 15 6"/>` for a back chevron); the earlier `←`/`→` glyphs got muddled across direction.

## Translation guidelines

When adding an Arabic translation:

- **Match the register of existing Arabic** in `arabic_definition`, `mnemonic_ar`, and `title_ar` in the same file (formal, scholarly).
- **Use established Tajweed terminology.** Izhar (إظهار), Idgham (إدغام), Iqlab (إقلاب), Ikhfaa (إخفاء), Ghunnah (غنّة), Qalqalah (قلقلة), Madd (مدّ), Tafkheem (تفخيم), Tarqeeq (ترقيق); technical terms, not to paraphrase.
- **Don't over-translate.** Quranic verses (`arabic`) and `arabic_definition` stay canonical; your translations are for UI chrome and rule explanations only.
- **When unsure, leave empty.** The UI falls back to English; an empty field beats a guess.

## Testing

After any i18n change, pass through both languages and dark mode:

1. Visit `/`, `/learn`, every `/learn/<id>` (9 modules), `/practice`, `/progress`, `/settings`, `/this-doesnt-exist` (404), and `/mushaf` plus a few mushaf pages.
2. Toggle the language pill on each; confirm no English in Arabic mode and vice versa.
3. Confirm `<html dir>` flips with the toggle.
4. Run `node scripts/verify-mushaf.mjs` for the Mushaf flow.
